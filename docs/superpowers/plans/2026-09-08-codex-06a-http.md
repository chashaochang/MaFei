## 实现语义

1. 请求总超时默认 30 秒，可由正数 `HttpRequest.timeoutMillis` 覆盖。外层 `withTimeoutOrNull` 覆盖连接、响应头、最终读体和全部重定向；Ktor 的每跳 request/connect/socket timeout 显式设无限，CIO requestTimeout=0，不存在每次跳转重置总预算。外部取消/外部 `withTimeout` 原样传播 CancellationException，不冒充本 Transport 的 HttpTimeoutException。
2. Ktor followRedirects=false，唯一重定向驱动是冻结的 `HttpRedirects.nextRequest`。301/302/307/308 保留方法和 body，303 清 body/content headers，预算 4；同源策略、跨源凭证剥离和 HTTPS→HTTP 拒绝不另写一套。中间跳转响应体不缓冲，立即取消通道后才发下一跳。
3. expectSuccess=false，4xx/5xx 正常返回 HTTP 响应；不安装 Cookie、Auth、retry、日志或解压插件，连接尝试固定 1。失败的 POST 不自动重放。只有调用者显式传来的 Cookie 会随请求发送，Set-Cookie 不写入任何隐藏 Cookie jar。
4. `BufferedAtMost` 边读边计数，最多多读第一个超限字节；支持未知 Content-Length/chunked。`Discarded` 不等待响应体并取消通道；`Buffered` 读取全体，最终 ByteArray 的物理上限为 Int.MAX_VALUE，溢出前明确失败而不是整数回绕。Negative limit 作为非法配置拒绝；0 limit 接受空体。
5. 读体结束必须检查 channel.closedCause。对明确有 payload 且非 Transfer-Encoding 的响应，另核对 Content-Length，不能把截断 JSON 当作成功。HEAD/1xx/204/304 不拿表示资源大小的 Content-Length 要求读体。
6. Header 多值保留：响应重复 Set-Cookie 不覆盖/拼成一项；请求普通重复 header 按 CIO 合并为逗号分隔，Cookie 为分号分隔。传入 Cookie 名称先规范为 `Cookie`，避免 CPF CIO 对 lowercase `cookie` 使用逗号的实测缺陷。不承诺请求物理 header 行数量不变，承诺协议值不丢失。
7. close 同时取消本 Transport 的在途子操作并关闭自己拥有的 client/engine，可重复调用；不会取消调用者其他任务。close 之后 execute 明确抛 HttpTransportException(Unknown, closed)。关闭是发出取消/释放信号，不是假装同步等待所有系统资源回收。
8. 传输错误沿 cause 链按 Java/Ktor 已知异常类别名分类：DNS、连接、TLS、明确 closed-write；普通 EOF/不明 SocketException 不猜成写失败而保留 Unknown。外层封装消息固定，不拼 body/header；保留原 cause 便于上层诊断，日志方仍需使用冻结脱敏器，不能打印原 URL/异常链当“已脱敏”。

## 本轮发现并修正的底层行为

直接读了本地对应 Ktor sources.jar 做证据，不依靠记忆猜 API：

- `io/ktor/client/engine/Utils.kt.mergeHeaders` 使用规范拼写比较 Cookie，lowercase cookie 的重复值会逗号合并。loopback 先复现 `a=1,b=2`，规范化后变为 `a=1; b=2`。
- `io/ktor/utils/io/ByteReadChannelOperations.kt.readAvailable` 在 isClosedForRead 时可返回 -1，而不直接抛 closedCause。新回归先复现“Content-Length 100、实际 5 字节仍成功”，修复后抛错误且 POST 只有一次请求。
- 仅依赖 statement cleanup 或只取消未消费通道，遇到 stalled body 仍可能让 CIO parser 等待。最终响应、Discarded、重定向均显式取消通道 **和响应 call context**，真实 socket 已验证断开；后者修复了全套双端执行时再次复现的 parser 清理竞争。
- CIO 收到 HTTP 101 时 body 是升级会话对象，直接 bodyAsChannel 会 NoTransformationFound。新增单测先红，再显式取消该响应上下文、返回 101 空体，避免升级连接泄漏。
