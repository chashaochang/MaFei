# 06E OHOS AssetStore 短凭证实现

## 范围和限制

实现 `platform:secure-storage-ohos` 的 `OhosAssetCredentialStore`，使用 CPF **2.2.21-1.0.0** 已内置的 `platform.AssetStoreKit.AssetApi` / `AssetType`，直接调用系统 C API。没有新 Maven 坐标、自建 cinterop、ArkTS 业务页面或 N-API 回调。

**这是短凭证后端，不是全部凭证场景完成。** AssetStore 面向约 1 KB 的敏感数据，本实现限制 MFS1 编码结果至 **1024 字节**，包含编码头；超限在任何原生写入前抛 `Unsupported`，保留旧值，不截断、不切片、不自动回退明文。通用 codec 的 1 MiB 上限不是所有平台存储都支持 1 MiB 的承诺。长 Cookie/JWT/RawBytes 需要后续 HUKS/系统保护密钥 + 有界密文文件方案，或先有真实 provider fixture 证明生产凭证均满足容量；当前不得将这个后端作为“通用大凭证支持”冻结。

依据：本机 DevEco SDK 与 CPF sysroot 的 `asset/asset_api.h`、`asset/asset_type.h`；API 11+，`libasset_ndk.z.so`，`SystemCapability.Security.Asset`。初次自建 cinterop 生成空声明，是由于工具链已经提供对应系统声明；已改用内置绑定并删除冗余定义，没有修改工具链或缓存。

## 契约实现

- 存储 policy：Device First Unlocked、Auth None、Sync Never；不设置 persistent-after-uninstall tag、不申请该持久权限。实际设备锁屏与卸载策略需要运行验收。
- 物理 alias：`MFA + version + namespace length + namespace bytes + alias UTF-8`，最大 256 字节；命名空间 1–64 字节 ASCII 标识。长度边界防止分隔符拼接产生跨 namespace 碰撞，不用无验证 URL 当 alias。
- 每次查询/删除同时限定完整物理 alias 和 `DATA_LABEL_CRITICAL_1` 的精确 namespace；列表只在该 namespace 下查 attributes，不读取所有条目的 secret。
- save：Add(Conflict Throw Error)；禁止覆盖时单个原子 Add，重复返回 AlreadyExists。允许覆盖时 Add→Update，竞争删除后重试最多 16 次，持续争用显式失败。
- read/exists 对原生返回条数、alias、blob 长度做校验；损坏/锁定/权限/服务故障不能被当作缺失。错误不含 alias、凭证或 raw cause。
- 列表每页 128、最多 10000 项，逐条验证物理 alias，稳定排序；超过上限失败，不返回截断列表。offset 分页不是跨进程快照，并发写入时可能改变页内容。deleteAll 先完整列举再按精确 alias 删除，不调用全应用清空。
- 在 Default dispatcher 执行，调用前取消门禁，批量操作和重试合作取消；已开始的同步系统调用可能提交，不承诺取消回滚。
- 编码/读取暂存字节在 finally 擦除；C attribute 缓冲用完清零，原生 resultSet 用 `OH_Asset_FreeResultSet` 释放。不宣称能控制系统内部副本。
